## 6. 根因分析

MANUAL 条件把完整 Schema 作为文本提供给模型，并使用 `json_object`，四次均成功。FACTORY 条件把完整 Draft 2020-12 Schema 直接放入 `response_format.json_schema`，四次均返回非 JSON 短文本。两组在同一执行窗口、同一模型和同一任务矩阵下出现稳定分化，首先指向 provider Structured Output 边界，而不是通用网络或凭据故障。

Moonshot 的 [Structured Output 文档](https://platform.kimi.com/docs/api/chat) 将支持范围限定为 MFJS；[MFJS 规范](https://github.com/MoonshotAI/walle/blob/main/docs/mfjs-spec.zh.md) 也说明，不支持的关键字不一定被接口拒绝，但不能保证稳定生成符合约束的输出。冻结 Pilot Schema 包含 `$schema`、`minLength`、`minItems` 和 `maxItems` 等不属于该子集的关键字。旧 fake-stream 测试只证明本地 OpenAI-compatible 调用签名正确，没有证明完整 Draft Schema 与真实 Moonshot Structured Output 兼容。

## 7. 修正方案

1. `MoonshotExperimentGateway` 在发出 FACTORY 请求前，把已验证的 Draft 2020-12 Schema 确定性转换为 MFJS provider schema。
2. MFJS 支持的结构关键字原样保留；本地专属约束从 provider schema 中移除，并以稳定 description hint 继续向模型表达。
3. 未识别的结构关键字不静默丢弃，而是在 SDK 调用前返回 `MOONSHOT_OUTPUT_SCHEMA_UNSUPPORTED`。
4. 完整原始 Draft 2020-12 Schema 保持不变，仍作为 MANUAL/FACTORY 共同的本地最终校验契约。
5. `GatewayFailure` 和失败 `RunAttempt` 允许携带成对的 `prompt_tokens` / `completion_tokens`；成功 attempt 仍强制要求 usage，任何半组 usage 都被 Pydantic 拒绝。
6. launcher 的实际成本汇总因此同时覆盖成功与已返回稳定 usage 的失败 attempt。

## 8. 后续门禁

本次修正改变 FACTORY provider-visible request bytes 和 usage journal 行为，所以旧 canonical Manifest 只能作为已执行 Pilot 的历史身份，不能授权修正后的再次调用。继续 M5.5 前必须：

1. 通过 Ruff、mypy、定向实验测试、全仓回归和冻结契约检查。
2. 提交修正源码，在 clean commit 上生成并验证新的 Pilot Manifest。
3. 由项目 owner 审阅代码差异、Manifest、模型 profile、完整 8-run、最多 16 次 attempt 和人民币硬上限。
4. 获得新的明确费用批准后，才可执行第三次真实 Pilot；不得自动重放当前证据目录。
5. 只有修正后 FACTORY Structured Output 兼容性通过、Pilot review 完成、正式 Manifest 冻结并经 owner 批准，M5.5 才能结束。
