## 3. 复算方法

离线管线在冻结 worktree 中运行，输入为冻结 definition、execution plan 和已 seal 的外部 journal；没有读取 API key，也没有调用 Moonshot。分析使用 seed `20260725`、10,000 次按任务分层的 bootstrap 和 95% 区间。第一次发布后用完全相同命令重放，score set 与 analysis checksum 均保持不变。

主分析采用 intention-to-treat（ITT）：执行失败按预注册最差值计入。这回答的是“采用整套工作流后会怎样”，而不是“只看成功请求时模型会怎样”。Succeeded-only 只作为失败影响的敏感性分析，其 decision 固定为 `not-evaluated`，不能替代主分析。

## 4. H1/H2/H4 结果

| 命题 | ITT 效应 | 95% 区间 | 预注册判定 |
| --- | ---: | --- | --- |
| H1 结构一致性 | -0.066666666667 | [-0.1, -0.033333333333] | `not-supported` |
| H2 知识遗漏相对降低 | -0.314685314685 | [-0.653467295548, -0.100594512195] | `not-supported` |
| H4 个性化非劣 | -0.066666666667 | [-0.133333333333, 0] | `insufficient-evidence` |

MANUAL 120/120 成功，FACTORY 112/120 成功。H1 的负效应对应 FACTORY 8 个执行失败；succeeded-only 的 H1 差异为 0，说明成功样本的 Schema 通过率相同，但整套 FACTORY 工作流的可靠性没有达到主分析要求。

H2 的绝对遗漏差定义为 `MANUAL omission - FACTORY omission`，结果为 -0.125，95% 区间 [-0.213888888889, -0.043055555555]。负值表示 FACTORY 遗漏更多，而不是降低遗漏。Succeeded-only 的相对效应仍为 -0.253496503497，因此 H2 的不利结果不能只归因于 8 个执行失败；当前知识注入方式没有在本任务集上转化为更高的事实覆盖率。

H4 的非劣界值为 -0.05，区间 [-0.133333333333, 0] 跨过该边界，因此既不能确认非劣，也不能按预注册规则判为明确不支持。Succeeded-only 点估计为 0.004166666667，但其非主分析身份不允许覆盖 ITT 的“证据不足”。

## 6. H5 审计验证

H5 在两个独立、全新的 SQLite 数据库中执行同一固定生产链，均得到字节相同的 `AuditVerificationRecord`。六个步骤全部通过，完整率为 1.0：

```text
prototype.registered
  -> instance.cloned
  -> knowledge.bound
  -> spec.exported
  -> evaluation.completed
  -> skill.promoted
```

每一步都同时回读对应的 Prototype、Knowledge、AgentInstance revision、AgentSpec、EvaluationReport、SkillTree/EvaluationSuite 或晋升后快照，并交叉检查 checksum 和 revision。删除 `skill.promoted` 的反例测试使完整率降为 5/6，不会产生假通过。

H5 verifier 是 M5.7 在正式生成实验冻结后实现的工程验证。它不读取模型输出，也不影响 H1/H2/H4；因此本报告只把它解释为“当前代码能恢复固定生产链来源”，不把它冒充为预注册的生成实验结果或公网生产审计证明。

## 7. 客观结论

本轮结果不支持“当前工厂工作流提高结构一致性”与“当前知识注入降低知识遗漏”两项假设，对“个性化非劣”也只有不足证据。这意味着项目的工程治理闭环已可复现，但当前 FACTORY 渲染/执行路径尚未把治理结构转化为 Writer 输出质量收益。

项目仍获得两个可辩护的工程结果：正式证据可以从冻结输入完整复算且幂等重放；固定生产链的来源关系可以由真实 SQLite 状态和审计事件交叉恢复。二者说明框架在可复现性和追溯性上有实现基础，但不能抵消 H1/H2 的负面实验结果。

下一轮研究应创建新的 experiment ID，优先定位 FACTORY 的 8 次无效响应以及 succeeded-only 仍较高的知识遗漏。不能修改本次 Prompt、Schema、知识正文或评分规则后继续沿用 `writer-validation-v1`。

- `kimi-k2.6` 是可变 alias；相同输入在未来无法获得 provider 级字节复现保证。
